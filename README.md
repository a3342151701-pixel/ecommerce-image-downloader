# 电商图片提取

Chrome 扩展（Manifest V3）。在淘宝、京东、拼多多商家版的商品详情页提取商品图，打开新页面勾选后下载为 PNG。

## 安装

1. 打开 `chrome://extensions`
2. 打开右上角「开发者模式」
3. 选择「加载已解压的扩展程序」
4. 选中本目录 `ecommerce-image-downloader`

## 使用

1. 打开支持的商品详情页
2. 点击页面右下角「获取图片」
3. 在新页面勾选图片，点击「下载所选」
4. 文件保存到浏览器默认下载目录的 `ecom-images` 文件夹。每批开始前会检查已有编号，从数字最小的未占用编号开始命名。

## 下载编号

每批下载开始前，扩展会通过 `chrome.downloads.search` 读取 `ecom-images` 中仍然存在的 `product-NN.png`，把这些编号视为已占用。新一批图片从最小的空号开始编号，遇到已占用编号则跳过。例如已有 `01`、`02`、`04`，本批会使用 `03`、`05`、`06`。

- 已从磁盘删除的图片，其编号会在后续批次中重新使用。每批开始时会触发 Chrome 重新检查文件是否存在，等待后再读取最新状态。
- Chrome 的文件存在性检查最多约每 10 秒刷新一次。若刚删除文件就立刻开始下一批，该编号可能暂时仍被视为占用，稍后重试即可。
- 正在下载的图片会提前占用编号。
- 某张图片下载失败时，它的编号在本批次中不会重新分配；下一批会优先补用这个空号。
- Chrome 下载记录被清空后，扩展无法感知仅存在于磁盘、已不在记录中的文件。此时仍使用 `conflictAction: "uniquify"`，不会覆盖已有文件，但文件名可能带 `(1)` 后缀。

## 支持的页面

| 站点 | 按钮出现条件 |
| --- | --- |
| 淘宝 / 天猫 | 地址是商品详情，例如 `item.taobao.com/item.htm?id=`、`detail.tmall.com/item.htm?id=` |
| 京东 | 地址类似 `item.jd.com/123456.html` |
| 拼多多商家版 | 仅 `mms.pinduoduo.com`，路径包含 goods，且是详情、编辑、预览，或带有 `goods_id` |

其他页面不会注入按钮。单页跳转后会重新判断，离开详情页时按钮消失。

## 图片从哪里取

- **淘宝**：页面上的主图、轮播图，以及脚本文本里的 `img.alicdn.com` / `gw.alicdn.com` 地址。缩略图后缀（如 `_400x400.jpg`、`_.webp`）会去掉。详情长图若在 `desc.alicdn.com`，由后台再请求描述页补充。
- **京东**：页面图片和 `jfs/...jpg` 路径。统一换成 `img14.360buyimg.com/n1/` 的较大图。描述地址（`cd.jd.com`、`dx.3.cn`）会再抓一次。
- **拼多多商家版**：页面图片和 `pddpic.com`、带 `img` 的 `yangkeduo.com` 地址，去掉 `imageView` 等缩放参数。

同一张图只保留一次。图标、logo、小于 80px 的已加载小图、以及非商品图床地址会被丢掉。单个站点抓不到图时，不影响另外两个站点。

## 权限

- `storage`：把本次提取结果临时交给新页面
- `downloads`：把转好的 PNG 保存到本地；读取下载记录中已有的编号，避免重复命名
- `tabs`：打开图片选择页
- 主机权限：只覆盖三个电商站点，以及它们的商品图床（阿里 CDN、京东图床、拼多多图床），用于读取详情描述和把图片转成 PNG

扩展不读取账号、Cookie 或订单。

## 已知限制

商品页结构经常改版。主图若既不在 `img` 上、也不在页面脚本和描述页里，这次提取会是空的。部分图床会拒绝扩展发起的下载请求，这些图片会记入失败数量，其余图片继续下载。
